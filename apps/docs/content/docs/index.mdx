Setting up a [Kiro](https://kiro.dev) workspace means writing a lot of files by
hand: agents, skills, slash commands, hooks, MCP config, spec templates.
Kiro-Kit writes them for you.

```bash
npx kiro-kit init
```

Pick the preset that matches your stack and it all lands in `.kiro/`. Presets
are **independent**: installing one never pulls in another, and removing one
doesn't break the rest.

## Why presets

A preset is a set of Kiro configuration files for one kind of work: frontend,
backend, mobile, devops, data and AI, and others. Instead of assembling agents
and commands yourself, you install a set that already knows the conventions of
that stack.

The [reference section](/docs/reference) is generated directly from the preset
manifests in the repository, so the catalog you read here is the catalog that
ships.
